# 設計と進め方

## 形

```
design-system（CSS）                https://github.com/3pino/design-system
        │
explorer-kit（共有の部品）          https://github.com/3pino/explorer-kit
  ├─ 画面     FileExplorer・FileProperties・EntryActions（＋ Button・Menu・Modal などの小さな部品）
  ├─ 決まり   名前・同名の扱い・移動とコピーの進め方・ゴミ箱の仮想フォルダ・並び順・フォルダごとの表示
  └─ 状態     開いているフォルダ・一覧の写し・選択・切り取り／コピーの控え・表示方法
        │                               │
     disnans                         fixplor
  置き場所: サーバーの共有フォルダ      置き場所: この端末（Rust）
  本体から貸す: アプリの既存の機能      本体から貸す: src/lib/host.svelte.ts
```

- disnans の中のエクスプローラーは、共有の部品に「サーバーの共有フォルダ」という置き場所を 1 つ渡したもの（subset）。
- fixplor は、同じ部品に「この端末」を渡し、その外側に専用の機能を足していくもの。Disnans のサーバーが無くても、ふつうのファイラーとして動く。
- 共有の部品は、design-system と同じく別のリポジトリで、タグを指定して取り込む。

## 2 つの口

共有の部品は、次の 2 つだけを通して外とやりとりする（`explorer-kit/src/types.ts`）。

1. **置き場所（`ExplorerApi`・`EntryUrls`・`Rules`・`ScopeSource`）** — 作るときに 1 つ渡す。OS や通信の違いは実装の中に閉じる。
2. **本体から借りる機能（`ExplorerHost`）** — 通知・確認・「戻る」・ファイルを開く・クリップボード・この端末の種類。

### 置き場所ごとの違いと、揃え方

| こと | Disnans サーバー | この端末（fixplor） | 揃え方 |
| --- | --- | --- | --- |
| パス | 共有フォルダからの相対（直下は空文字） | OS の絶対パス（`/a/b`・`C:\a\b`） | 部品のパスは「いちばん上からの相対・区切り `/`」に統一。この端末は `src/lib/fs/mapping.ts` で対応させる（POSIX のいちばん上は `/`、Windows はドライブの一覧） |
| ゴミ箱 | サーバーの `.trash/`（一覧・戻す・完全に消す） | OS のゴミ箱（ここからは戻せない） | `caps.restore`。偽なら「取り消す」を出さず、確認の文も変える |
| 特別なフォルダ | `attachments/`（名前を変えられない・フォルダを作れない） | なし | `Rules.attachmentsDir`（無ければ `null`） |
| 名前の決まり | Windows でも使える名前だけ | OS の決まり（POSIX は `/` 以外ほぼ自由） | `Rules.nameError` |
| 見る（サムネイル・中身） | 認証つきの URL | Tauri の asset の URL | `EntryUrls` |
| ファイルを押したとき | 拡大表示・ダウンロード | OS の既定のアプリで開く | `ExplorerHost.viewerKind`・`download` |
| 置き場所が変わる | 接続先のサーバーを切り替える | 変わらない | `ScopeSource`（省くと、変わらない置き場所） |
| 失敗の種類 | `exists`・`parent_missing` など | 同じ名前に揃えた（Rust の `FsError.code`） | 文にするのは `ExplorerHost.errorText` |

## 進め方

| 段階 | すること | 状態 |
| --- | --- | --- |
| 0 | fixplor の土台。Rust のファイル操作と試験 | 済み |
| 1 | disnans のエクスプローラーを、2 つの口ごしに動く形へ直す（挙動は変えない） | 済み |
| 2 | 共有の部品のリポジトリへ移し、disnans がタグ指定で取り込む | 済み（explorer-kit v0.1.0） |
| 3 | fixplor の画面を、共有の部品に置き換える | 済み（この端末の一覧・選択・コピー・移動・名前の変更・新しいフォルダ・ゴミ箱・プロパティ） |
| 4 | fixplor 専用の機能（下の「これから」） | これから |

## 決めたこと

- **ファイルの操作は Rust のコマンド（`fs_*`）だけ**。Tauri の fs プラグインは入れない（画面に渡す権限を増やさない）。
- **黙って上書きしない**。同名は `exists`。上書きを明示したときだけ、ファイルをファイルで置き換える（フォルダは置き換えない・混ぜない）。
  画面は、上書きの前に必ず確認する（共有の部品の決まり）。
- **コピー・書き込みは、宛先のフォルダの一時の名前へ書き終えてから付け替える**。失敗しても、宛先に書きかけを残さない・前の中身を壊さない。
- **消すのはゴミ箱だけ**。ゴミ箱へ入れられないとき、完全に消す方へ切り替えない。
- **シンボリックリンクは辿らずに写す**。一覧では、辿った先の種類を出す（フォルダへのリンクは開ける）。
- **隠しファイルは、置き場所の側で除く**（共有の部品は、隠すという考えを持たない）。切り替えたら一覧を読み直す。
- 画像のサムネイルのために、asset の URL を全部のパスに許している（`tauri.conf.json` の `assetProtocol`）。ファイラーなので、読める範囲は絞っていない。

## これから（段階 4）

機能:

- Disnans のサーバーを「場所」として足す（ログイン。置き場所をもう 1 つ作り、左の一覧から切り替える）
- タブ・2 画面（共有の部品は、エクスプローラーを何個でも作れる形になっている）
- 画像・PDF の拡大表示（いまは、どのファイルも OS の既定のアプリで開く）
- OS からのドロップ（ほかのアプリからファイルを落とす）と、OS のクリップボードのファイルの貼り付け
- 検索、長いコピー・移動の進み具合と中止、フォルダの見張り（ほかのアプリの変更を、読み直さずに映す）
- OS のゴミ箱の中身を見る・戻す

足りないところ:

- 外枠（上のバー・左の場所の一覧）の見た目は仮。利用者の確認を取っていない。
- 手元で動かしたのは Linux だけ。Windows は CI でビルドと Rust の試験を通しているが、画面は動かしていない。Android は未着手（OS のゴミ箱が無く、`unsupported` を返す）。
- UTF-8 でない名前のファイルは、一覧には出るが操作できない。
- 移動は「同名が無いことを確かめてから付け替える」ので、そのあいだに別のアプリが同名を作ると上書きになる（Linux では `renameat2` で防げる）。
- CSP は未設定（`null`。disnans と同じ）。外の内容は読まないので、あとで締める。
- サムネイルは、縮小版を作らず画像そのものを読む（大きい画像の多いフォルダは重い）。
- 共有の部品の小さな部品（Button・Menu・Modal など）は、disnans の `components/ui` の写し。disnans の側は自分のものを使い続けているので、同じものが 2 か所にある（一本化は別の作業）。
